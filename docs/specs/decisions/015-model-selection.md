## 背景

作者倾向使用国内厂商的模型。项目中模型有多个角色：开发主模型、本地主模型、本地小模型（工单理解与微调对象）、评测对照的强模型、合成数据生成模型，以及 2×2 中 Claude Code 对照组。产品前提是"代码和数据不出部署方"，所以主模型必须能本地部署；作者的 Mac 只有 16GB 内存；开发与评测使用公开数据，可以用 API。

## 备选方案

主模型需同时满足：有开源权重且许可证允许商用；单机一两张 GPU 能部署；擅长 agent 编码、工具调用稳定；有 API 版本。

| 厂商 | 情况（2026 年下半年，来自第三方资料，待官方核实） | 是否适合做主模型 |
|---|---|---|
| Qwen | 型号梯度最全，从几 B 到上万亿；有专门的编码 agent 模型（Qwen3-Coder-Next 80B-A3B、Qwen3.6-35B-A3B）；多数 Apache 2.0 | 适合 |
| DeepSeek | V4.x，API 极便宜，MIT；开源权重数百 B | 单机难部署，不适合做本地主模型 |
| Kimi | K2.6，开源模型中 agent 编码能力居前；万亿级 | 单机难部署，适合做对照 |
| GLM、MiniMax | GLM-5.1、M2.7，能力接近 | 许可证与规模未查到 |

开发主模型用旗舰闭源 API 还是可部署模型的 API：前者效果可能更好，但上线时无法本地部署同一模型，效果和评测结论都不能迁移；后者开发与上线是同一模型，切换才接近"只改配置"。

## pi 的做法

pi 通过 pi-ai 支持多家模型与 OpenAI 兼容的本地服务（`models.json`），不规定使用哪家模型。

## 决定

| 角色 | 选择 |
|---|---|
| 开发与日常评测的主模型 | 可本地部署的 Qwen 开源编码模型的 **API 版本**：候选 Qwen3.6-35B-A3B（倾向）与 Qwen3-Coder-Next，在 T2 用开发集小子集比较后选定 |
| 本地主模型（产品默认） | 与开发主模型为**同一模型**，T13 在租用的 GPU 上部署 |
| 本地小模型 / 微调对象 | Qwen 3.x 的 4B 左右指令模型，可在 16GB Mac 上运行 |
| 评测对照的强模型 | Kimi K2.6（API） |
| 合成数据生成 | DeepSeek V4.x（API），与所有被评测模型不同家 |
| 2×2 的 Claude Code 组 | Claude，唯一例外，只用于公开数据的评测 |

所有模型锁定版本；版本变化后旧评测结果不能直接比较。

## 理由

- Qwen 是唯一同时满足"API 开发、单机部署、小模型微调"的家族；开发与上线用同一模型，评测结论可以迁移。
- Kimi 作为不同厂商的能力上限参照；DeepSeek 便宜且与评测对象无关，适合生成数据。
- 最终主模型由本项目自己的评测选定，而不是引用厂商或第三方跑分。

## 后果

- T1 开工前核实：候选模型的 API 平台与价格、经 pi 调用时工具调用是否正常、各模型训练截止日期（决定留出集起始月份）、许可证。
- T2 增加主模型选型的小规模对比。
- T13 部署同一主模型并对比本地与 API 版本的差距；工具调用解析的配置是常见的坑。
- 作者需准备百炼（或硅基流动）的 API key；Kimi 与 DeepSeek 的 key 到 T2 才需要。
