# 017：主模型直接定为 Qwen3.6-35B-A3B，Kimi 经百炼调用

- **状态**：已确认
- **日期**：2026-11-25
- **相关**：proposal.md 第 5 节（模型） ／ design.md 3.11 ／ tasks.md T2 验收 6、10 ／ 部分取代 `015-model-selection.md`（主模型的选定方式、Kimi 的调用渠道、版本锁定的口径）

> 本记录确认后不再修改正文。改变决定时，新写一份记录，并把本记录的状态改为"已被 NNN 取代"。

## 背景

015 定了两件要在 T2 落实的事：主模型在 Qwen3.6-35B-A3B 与 Qwen3-Coder-Next 两个候选中用开发集小子集比较后选定；评测对照的强模型用 Kimi K2.6。T2 开工核实（`docs/reviews/step02-eval-framework.md`「0. 开工核实」，2026-11-25）发现：

1. `qwen3-coder-next` 在百炼北京端点返回 404 `model_not_found`，当前 key 可见的 191 个模型中没有它；T1 开工核实（0C）时同样调不通。
2. Moonshot 官方文档已把 `kimi-k2.6` 标为停用：K2 系列 2026-10-31 起不再开放新注册，预计 2026 年 12 月底全部下线。百炼上的 `kimi-k2.6` 用现有百炼 key 可以调用（输入 / 输出 6.5 / 27 元每百万 token）。
3. T1 收尾记录的偏离：API 模型没有带日期的快照，「所有模型锁定版本」对 API 侧只能做到锁定模型 ID（T1 实现说明「T1 收尾」5.5 第 3 条，当时约定到 T2 追加记录）。

## 备选方案

| 问题 | 方案 | 优点 | 缺点 |
|---|---|---|---|
| 第二个候选 | A. 换成百炼可用的 `qwen3-coder-flash` | 保留「由本项目评测选定」 | 与开源权重的对应关系待核实；多花选型费用 |
| | B. 另找渠道调 Qwen3-Coder-Next | 保留原候选 | 需新 key；平台不同，价格与延迟可比性变差 |
| | C. 去掉选型，直接用 Qwen3.6-35B-A3B | 省下选型花费与时间；015 本就倾向它 | 015 的「由本项目评测选定」不再成立 |
| Kimi 渠道 | A. 经百炼调用 `kimi-k2.6` | 与 Qwen 同一 key、同一张账单，对账简单；模型不变 | 百炼托管多久未知 |
| | B. Moonshot 官方端点 | 官方渠道 | 新注册已关闭；12 月底下线后无法复现 |
| | C. 换成 `kimi-k3` / `kimi-k3.1-pro` | 不会马上下线 | 偏离 015 的对照模型；价格与能力未核实 |

## pi 的做法

pi 通过 pi-ai 支持多家模型与 OpenAI 兼容端点，不规定使用哪家模型，也不规定渠道。

## 决定

作者 2026-11-25 决定：

- **主模型**：直接定为 Qwen3.6-35B-A3B（百炼 `qwen3.6-35b-a3b`），T2 不做主模型选型；T13 本地部署的仍是同一模型。
- **评测对照的强模型**：仍为 Kimi K2.6，经百炼调用（`kimi-k2.6`），不走 Moonshot 官方端点。
- **版本锁定口径**：API 模型锁定到模型 ID 与调用渠道；平台没有带日期的快照，同一模型 ID 背后的权重可能被平台更新，评测报告写明运行日期。

## 理由

- 第二个候选在现有渠道上不可用，另找渠道或换模型都要付出额外的核实与花费；015 本来就倾向 Qwen3.6-35B-A3B，它已在 T1 验收中经 pi 完成任务。
- Kimi 只作对照，不参与选型；经百炼调用模型不变，又避开了官方端点下线带来的不可复现。

## 后果

- 「主模型是本项目评测选出来的」这一说法不再成立，简历与报告不得这样写；只能说「主模型按 015 的倾向选定，T2 测了它的基线」。
- 以后若要换主模型，需新写决策记录，并在开发集上与当前主模型做配对比较。
- 百炼可能停止托管 `kimi-k2.6`。留出集重新启用、需要重跑 T2 基线时（tasks.md T2 验收 1），若届时调不到，就重新选对照模型并写新的决策记录。
- `MOONSHOT_API_KEY` 在 T2 中不使用。
